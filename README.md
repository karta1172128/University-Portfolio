# University-Portfolio

委託人的 React 履歷與作品集。專案規則見 AGENTS.md，委託人與使用者是不同的人；不將專案資料寫入 GPT 帳戶記憶或雲端文件。codebase memory MCP 的本機快取限制也記載於該文件。

## 直接在畫面編輯文字

在專案資料夾的 VS Code PowerShell 執行：

~~~powershell
npm.cmd run edit
~~~

開啟終端機顯示的 Local 網址，就會出現本機內容編輯工具列。點選虛線框內的文字直接輸入；段落可換行，標題等單行欄位按 Enter 結束編輯。

- 「預覽排版」暫時隱藏編輯框，檢查實際閱讀效果；按「繼續編輯」回到編輯模式。
- 可重複的文字清單旁直接顯示「＋」按鈕，點擊新增文字框；項目旁的 × 移除該項，↑／↓ 調整順序。適用基本資料、介紹段落、技能、相關經歷及其段落與連結、作品負責項目、標籤、介紹／玩法區塊及段落、時間軸內容與連結。固定只有一格的標題或摘要仍直接修改。標籤與負責項目可全部刪除後重新加入。
- 「進階設定」開啟備用的內容管理視窗，可選擇自我介紹、個人技能、網站與聯絡資料或任一作品，增刪與排序清單、修改選填欄位與連結；視窗內先編輯草稿，按「套用到畫面」後才影響預覽。
- 「復原／重做」保留本次開啟編輯器後最近 50 步文字與清單操作；它與 Git 版本不同，不會在關閉後保留。若復原了已儲存的內容，仍需再按儲存才會寫回專案。
- 製作背景使用 team 單一選填欄位，接在卡片頂端的類別／獎項後方；負責內容使用 responsibilities 清單，每項獨立編輯。資料 schemaVersion 為 2，不再將原有兩行任務的第一行當成製作背景，也不使用舊 role 欄位。背景未確認時留空，人數不自行推定。
- 「儲存到專案」把變更寫入 src/data/content.json，重新載入仍會保留。儲存不會自動提交 Git 或發布網站。
- 「放棄修改」回到最近一次成功儲存的內容；已儲存版本的還原由 Git 管理。
- 相關經歷區塊可直接按「＋相關經歷」新增，類別與補充資訊可留空；時間軸按「＋經歷」新增，直接編輯名稱、日期、職稱、工具與內容。所有增刪先是草稿，儲存後才寫入檔案。
- 閱讀模式不顯示空白的類別與補充資訊，兩者都空白時說明會使用整列寬度。編輯模式保留提示框，方便重新填入。政府計畫與專案協作的作品連結分別放在對應段落下方，其餘經歷也可依需要在內容管理中增刪連結。
- 經歷的 links 可設定 afterParagraph（從 0 起算），指定接在哪段說明後；未設定則放在最後一段下方。對應段落下方可直接按＋新增連結並輸入文字與網址；移動或刪除段落時會同步調整連結位置，刪除附有連結的段落時，連結會保留在相鄰段落下。進階設定也可指定段落序號，畫面從 1 開始。
- 進入作品頁也能編輯作品名稱、摘要、職責與介紹。每個段落使用自己的文字框，Enter 可在同一框內換行，＋新增下一個段落；標題是獨立的固定文字框。跨頁前須先儲存或放棄修改；直接重新整理或離開頁面則由瀏覽器提示。草稿不存進瀏覽器儲存空間，關閉後不能恢復未儲存內容。

這是沿用既有版型的內容編輯器。基本資料、介紹段落、技能、相關經歷、標籤、作品介紹與玩法區塊皆可增刪及排序；選填文字可留空，也能補上原先沒有的欄位。技能名稱可改，已知技能搭配既有標誌，自訂名稱使用文字縮寫。已有作品圖片可排序、移除及選擇封面，封面必須保留在清單中；這不會刪除圖片檔。新增作品頁、上傳新圖片、自由拖曳版面與更改路由仍需透過專案流程處理。技能小標題不再顯示。電子郵件集中在底部聯絡區，可於該處編輯。按鈕、導覽與法律聲明等介面文字不屬於可編輯內容。

編輯功能僅在明確啟動 edit 的本機開發服務提供；一般 dev、preview 與正式建置均不開放寫入。儲存端只接受同一本機來源、有編輯連線識別且版本相符的請求，固定寫入 content.json。若別的視窗或程式已改過檔案，會拒絕覆寫並提示；此時先複製保留你的文字，再重新載入最新內容。

## 經歷時間軸

- 位於自我介紹之後；原有相關經歷保留。資料放在 profile.workExperiences，閱讀版在沒有資料時隱藏此區塊，編輯版提供新增入口。
- 採橫向時間軸，每個節點下方直接顯示期間、標題、職稱與工具、工作／學習內容，不另設重複的摘要列或大型卡片。職稱與工具同列，空白省略、窄畫面自然換行。
- 畫面依開始年月由早到近排列，左舊右新，初次開啟停在最右側最新經歷。排序僅影響呈現，編輯仍綁定原始資料索引。「曾經 ←」「→ 目前」固定在拖曳視窗左右兩側、時間線上方，以青綠色半粗體提示時間方向；標示位於移動軌道與淡出遮罩之外，不隨節點拖動。移除標題旁的範圍文字、節點旁的「目前」標籤、返回按鈕與底部拖曳文字／項數。日期中的「至今」保留，實心圓仍依 current 欄位顯示，中央為 16px 並保留靜態外環，單層清晰光圈在約 0.9 秒內擴散至直徑 44px 後淡出，再停頓約 2.1 秒，每 3 秒循環一次；啟用減少動態效果時停用光圈動畫。
- 重用早期橫向版本的拖曳、速度投射與端點阻力。第一項靠左、最後一項靠右，中間項目盡量置中；停止位置依整列邊界限制，避免兩端留下大塊空白。可點選項目或用左右方向鍵、Home、End 切換。減少動態效果設定會停用過場。
- 左右淡出依目前項目切換，旁邊露出其他經歷；三項示範在寬螢幕也超過顯示範圍，可直接試拖。上下滾輪保持整頁正常捲動，不攔截或轉成橫向。觸控使用水平拖曳，垂直手勢保留給網頁。
- 整列保留所有項目的高度，切換不改變下方版面。明確展開長內容或編輯內容時，高度可隨內容增加；無內部直向捲動框。
- 編輯模式點「＋經歷」直接新增空白項目，再填經歷標題／公司或學校名稱與起訖年月（或持續至今）。職稱、工具、工作／學習內容與連結皆選填；學生與自主學習期間不用填職稱，空白時不占一行。
- 標題、職稱、工具、內容與日期都在畫面直接編輯；按＋新增內容段落，Enter 在段落內換行，閱讀版保留換行。
- 短內容直接完整顯示；超過 260 字或 5 行時先顯示最多 3 行、220 字的摘要，讀者可用「更多內容」展開全文並收合。編輯時始終顯示全文，不截斷儲存資料。相關作品連結顯示在內容下方。
- 每個連結分別填寫顯示文字及網址，也支援 projects/作品id/index.html。站內同分頁，外部另開分頁並標示。
- 新增後會選取新項目；每筆經歷可直接移除，畫面順序由開始年月自動決定。所有變更先是草稿，須按工具列的「儲存到專案」保存。
- 「試看內容示範」僅供本機編輯版試看虛構資料，不寫入履歷或包含在發布程式內。
- 直向改版前的已填資料已保存於本機 Git cca146d；最初時間軸試作前還原點為 6f03b21。還原前先保存後續文字變更，再決定還原範圍。

## 啟動與驗證

### 圖片最佳化

原始作品圖片保留在 `projects/作品id/`，大頭貼保留在 `images/me2.jpg`。啟動本機服務或正式建置時，會在本機透過 sharp 自動產生 WebP，不使用線上轉檔服務。卡片提供 320／640px 版本、作品頁展示使用最長寬度 1280px、縮圖使用 320px；點擊放大才載入最長寬度 2560px 版本，較小原圖不會放大。大頭貼提供 240／480px 版本。

產物位於正式建置的 `dist/media/`，暫存位於已忽略的 `node_modules/.cache/portfolio-media/`，不手動維護或提交這些產物。取代同檔名原圖後會依檔案內容重新轉換；本機服務可偵測既有圖片變動，新增作品／圖片註冊後請重啟服務。瀏覽器與建置共用 `src/image-paths.js` 的命名規則；變更輸出設定時須一併更新快取版本。

在本資料夾的 PowerShell 執行以下指令。電腦須先有 Node.js 與 npm；若顯示找不到 npm，先處理工具安裝及 PATH，npm install 本身不會安裝 npm。

~~~powershell
npm.cmd run dev
~~~

目前已安裝套件時可直接啟動。開啟終端機顯示的 Local 網址，按 Ctrl+C 停止；開發期間儲存元件與樣式會更新預覽。這些指令不需要系統管理員權限。

完整驗證與建置結果預覽：

~~~powershell
npm.cmd run check
npm.cmd run preview
~~~

check 會依序驗證內容、產生 HTML 入口、建置網站並執行測試；任何步驟失敗都會停止。preview 只讀取最近一次的 dist/，修改程式後須先重新建置。

其他指令：

| 指令 | 用途 |
| --- | --- |
| npm.cmd run build | 檢查內容、產生入口並建置 dist/ |
| npm.cmd test | 執行測試，需先有最新建置 |
| npm.cmd run prepare:pages | 只檢查資料並更新 HTML 入口 |

需要重新安裝套件時，沿用專案的 pnpm-lock.yaml，以 pnpm.cmd install --frozen-lockfile 安裝。日常執行 npm.cmd run dev/build/check 不會另建 npm 鎖檔；不混用 npm install 與 pnpm install 維護兩份鎖檔。若只有 npm，可先依 pnpm 官方方式安裝 pnpm，再依此鎖檔還原套件。

已在 Node.js 26.13.1 驗證；套件版本由 package.json 與 pnpm-lock.yaml 管理。本機文字編輯功能未新增相依套件。

## 結構與修改位置

~~~text
src/
  App.jsx                 頁面選擇與共同外框
  pages/                  首頁、作品列表、作品詳細頁
  components/             導覽、個人介紹、技能、聯絡及作品卡片
    viewers/              圖片瀏覽器與影片播放器
  content/                共用文字元件、本機編輯介面與儲存格式檢查
  data/
    content.json          履歷、經歷、技能、網站文字與作品的唯一內容來源
    site.js / skills.js   提供內容給頁面與建置流程使用
    projects.js           作品註冊順序、分類與首頁精選
    pages.js              根據作品資料建立入口清單
  styles/
    index.css             唯一樣式入口，決定載入順序
    tokens.css            色彩、字級、間距與頁面寬度的共用設定
    base.css              基礎樣式、共同元件與響應式規則
    carousel.css          兩種橫向區塊的共用軌道樣式
    resume.css            首頁個人介紹與經歷
    portfolio.css         卡片、作品頁及圖片瀏覽補充樣式
tooling/                  內容檢查、HTML 產生與素材建置
projects/                 原始截圖與自動產生的作品 HTML 入口
images/                   個人照片、圖示及官方 SVG 來源說明
legacy/                   未載入的舊版 CSS 與 JavaScript
previews/                 歷次本機畫面紀錄，不加入發布產物
tests/                    內容、擴充流程與建置產物檢查
~~~

首頁維持「自我介紹 → 經歷時間軸 → 相關經歷 → 技能 → 作品 → 聯絡」。自介、經歷、技能與作品文字統一在 src/data/content.json，信箱由各處共用，底部以可選取的純文字呈現，寄信與複製僅由兩個按鈕操作；ProfileSections.jsx 只負責呈現。官方 SVG 在 images/skills/，來源和使用說明保留於該資料夾。

資料檔負責內容，pages 負責排列，components 負責可重用操作，styles 負責外觀。useHorizontalDrag.js 集中兩種橫向區塊的手勢、端點阻力與誤點防護，carousel.js 集中位置與吸附計算；content/work.js 僅管理經歷資料。tokens.css 管理主題，carousel.css 管理共用軌道樣式，其餘依版面分檔。一般文字調整不需要修改建置流程或複製元件。

## 首頁作品卡片

- 「瀏覽全部作品」使用低調外框按鈕；各卡片的「查看作品介紹」加上小箭頭，以距離文字 4px 的文字底線呈現，仍保留點擊內距。此卡片樣式也套用至全部作品頁。

- 所有作品合併為同一列橫向卡片，移除「其他作品」收合區。所有作品均顯示完整卡片；大小與明度依卡片進入顯示範圍的比例變化，進入主要範圍恢復正常，退出時縮至 90% 並淡出，不依作品身分區分，也不以滑鼠懸停改變。
- 桌面顯示三張主卡片，平板兩張、手機一張；中間各組左右皆露出部分相鄰卡片，兩端則靠齊邊界，不留空白。可從圖片或卡片留白橫向拖動，放開後吸附；正常點擊圖片與連結仍前往作品，上下滾輪繼續捲動整頁。不另設箭頭按鈕；支援左右方向鍵與 Home／End；減少動態效果時取消過場。
- 作品順序與精選由 projectOrder／featuredIds 維護，沿用 ProjectCard 與既有作品資料，全部作品頁不改成輪播。

## 新增或調整作品

1. 在 src/data/content.json 的 projects 物件中複製最接近的作品資料，用新的英文 id 作為鍵名，並填入相同的 id 欄位。id 同時是網址及素材資料夾名稱，既有 id 不任意更改，以免破壞連結。
2. 填入 title、category、group、type、summary、tags、images、cover 與 sections。group 使用 projects.js 中穩定的分類 id：Special、Junior 或 Sophomore。
3. 把圖片放進 projects/該作品id/，在 images 依序列出檔名；cover 必須是其中一張。不要只放圖片而忘記加入清單。
4. 在 src/data/projects.js 的 projectOrder 加入該 id，決定列表及下一個作品的順序。要放到首頁精選時，再調整 featuredIds；其餘作品接在首頁橫向卡片列後方，所有卡片依目前顯示位置淡入放大或淡出縮小。
5. 執行 npm.cmd run check。工具會建立作品 HTML 入口，依資料更新頁面標題與摘要，並檢查缺圖、重複 id、分類與連結。新增入口需一併加入本機 Git。

tags 可為空清單；team 為製作背景／合作方式，responsibilities 為負責內容清單，兩者皆選填；responsibilities 使用空陣列表示不顯示。

可選欄位包括 fullTitle、team、responsibilities、award、client、download、external、video、sectionsTitle、mechanics 和 mechanicsTitle。video 使用 YouTube 影片 id；download 與 external 使用完整 HTTPS 網址。pageTitle 可覆寫瀏覽器標題，未填時使用作品名稱與 site.name。

新增分類只需在 projects.js 的 projectGroups 增加 id 與顯示名稱，再把作品指派到該分類；列表會自動顯示。變更分類的顯示名稱不影響分類錨點。

既有 HTML 入口是產物，會標示 Generated，不直接編輯。執行 dev 或 build 時自動更新；只想同步入口時使用 prepare:pages。開發伺服器執行中新增或移除作品，完成清單更新後重新啟動 dev。產生器不自動刪除舊資料夾；移除作品時須另外核對舊入口及經歷連結。

分析與撰寫程式須使用 codebase memory MCP；索引是否更新依工具回報的狀態、新鮮度及建議判斷，不在每次修改後固定重建。完整規則見 AGENTS.md。索引不取代建置和測試。

## 配色切換

- 預設為霧藍，目前先隱藏所有頁面的配色切換按鈕，並固定使用霧藍，不套用先前瀏覽器保存的配色。五組配色與切換元件仍保留；將 src/theme.js 的 themeSwitcherEnabled 設為 true 即可恢復選單與已保存的偏好。
- 「配色」選單提供青綠、霧藍、暖砂、石墨、暖白五組。前四組為深色，暖白為淺色；只切換背景、文字、按鈕與框線，不改圖片或履歷內容。
- 主題定義集中在 src/theme.js；瀏覽器只保存配色 id，跨頁與重新整理沿用選擇，不連線上傳，也不保存任何履歷資料。瀏覽器禁止儲存時仍可當頁切換。
